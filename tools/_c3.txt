Deploy the account Worker, and fix PBKDF2 rounds Cloudflare refuses

- KV namespace created and bound; TOKEN_SECRET set; the Worker is live at
  https://nong-trai-account.w46824884.workers.dev
- PBKDF2_RoUNDS was 150000. Workers reject a deriveBits call asking for more than
  100,000 iterations, so register and login answered a bare "server" and the password
  path was broken on arrival. The value is now clamped in code rather than trusted from
  the config, because a var that kills the endpoint is worse than one that is ignored.
  100,000 is below OWASP's current 600,000 recommendation; that gap is the platform's
  ceiling and is stated in worker/README.md rather than left to look deliberate.
- tools/smoke-worker.ts exercises the deployed Worker over real HTTPS: register, login,
  push, read back, conflict resolution by savedAt, password change, and the three ways a
  Google token must be refused. Added because every local suite runs on Node, where the
  PBKDF2 ceiling does not exist - which is exactly why the broken setting shipped.
