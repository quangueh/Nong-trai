Set Cross-Origin-Opener-Policy so Google's popup can deliver a token

Google's popup sets COOP: same-origin on itself. This page set nothing, so the browser
placed the two in separate browsing context groups and refused the postMessage that
carries the credential back - "Cross-Origin-Opener-Policy policy would block the
window.postMessage call".

same-origin would be worse than absent, because it isolates this document explicitly.
same-origin-allow-popups is the value that isolates the page while still letting a popup
hold a reference to its opener, and it is what Google Identity Services requires.

Set in both deployment targets: vercel.json for Vercel, public/_headers for Cloudflare
Pages. Only one would have been enough for a given host, and having both means moving
between them does not silently reintroduce the fault.

Reported, not fatal, in verify:prod. vite preview does not serve host headers, so the
check always reads absent locally; failing on it would make the harness permanently red
on every developer machine for something only a real deployment can show.
