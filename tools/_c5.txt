Fix the broken Google button, and add the sign-in gate

Google sign-in did not work at all. Google's Identity Services require initialize()
before renderButton(), and the console said so - "Failed to render button before calling
initialize()". This module had them the other way round: initialize lived inside
requestGoogleIdToken, which only ran when a button was pressed, so the button never
painted and the fallback it left behind did nothing but wait out a 60 second timeout.
The one symptom was a log line that reads like a warning rather than the total failure
it was. Initialisation is now a separate idempotent step that both entry points wait on,
and the fallback drives prompt() with display:"popup" so it can actually open a chooser.

Sign-in gate, as asked: to play you must be logged in, and a login is remembered for 30
days. It stands down when no Worker is configured - with nothing to authenticate against
a wall has no door behind it, and locking a player out of their own garden over an
unreachable third party is the worst failure available. "Chơi không cần tài khoản" is
session-scoped: one visit, then the gate returns, because a persisted bypass is a hole
nothing closes.

The grace period is satisfied by a timestamp, not by a token being present. A token that
is present but expired is the case grace exists to cover.

Layout bugs found by photographing it: .gpanel-btn's display:flex outranks the UA's
[hidden], so the "hidden" fallback stayed on screen beside Google's real button; and the
slot was a flex row, so the two alternatives split the width and squeezed into narrow
columns with the label wrapped over five lines.

Password fields are in a real <form> now, shared by the gate and the account sheet.
Chrome refuses to offer a password manager for a password field outside a form, and logs
a DOM warning about it - a security feature degrading into a console complaint.

verify:prod separates third-party failures from its own. accounts.google.com answers 403
on any machine where localhost is not an authorised origin, which it should not be, and
counting that as a build failure means the harness only goes green on a configured
developer laptop. Nothing is hidden: our own host stays fatal, and a probe confirms a real
page error still exits non-zero.
